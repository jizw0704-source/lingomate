# Windows 与 Mac 功能、外观对齐准备

日期：2026-10-13。状态：本清单记录实施前准备；后续 0.1.17 已完成本机构建、自动回归与隔离界面检查，尚未安装或真实键盘验收。最终结果见[实施记录](WINDOWS-MAC-PARITY-IMPLEMENTATION-2026-10-13.md)。

用户要求 Windows 的功能、外观、操作行为和默认设置尽量与 Mac 主线一致。范围覆盖整个产品，包括候选窗、菜单、统一设置、学习、记忆、翻译和更新。用户已明确要求补齐 API 设置和 AI 翻译，功能与界面一起对齐；实施从 Claude 完成当前故障修复并交接后开始。

本清单编写时只完善接手文档、核对远端参考及本地源码，没有修改实现、构建、安装、切换输入法或进行真实键盘测试；下文的缺失状态与“未运行”保持为准备阶段快照。Claude 的 0.1.16 修复随后形成已通过物理键盘验收的 PR #7 基线。当前实施进度、0.1.17 功能与实际验证边界统一记录在 [对齐实施记录](WINDOWS-MAC-PARITY-IMPLEMENTATION-2026-10-13.md)，不从本历史表推断现在仍缺少全部对应模块。

## 1. 固定参考与对齐原则

Mac 参考提交为 `a599b738bef28662ae92d975b8ad3dd33b3f7306`，对应 Mac 0.12.9 / build 31。以[主线功能基线](https://github.com/jizw0704-source/lingomate/blob/a599b738bef28662ae92d975b8ad3dd33b3f7306/docs/MAC_FEATURE_BASELINE.md)作为功能和共同验收入口；字号及相关界面源码已通过 [PR #6](https://github.com/jizw0704-source/lingomate/pull/6)纳入主线。相同版本号不能证明源码和界面相同。

后续每项对齐记录 Mac 固定提交、相关源码、行为和截图。Mac 文档与渲染代码有差异时，先记录差异，再以该提交的实际实现核对；涉及预期行为的争议交由双方维护者确认。当前参考仍有未完成的实机及服务验收，不能写成全部功能已可用。

用户可见的功能、文案、布局层级、颜色、设置和快捷键保持一致。TSF、凭据存储、安装登记、系统菜单载体及 DPI 适配使用 Windows 原生方式；平台限制单列，不用相似的界面宣称功能已经完成。Mac 专属 Apple Translation 需要 Windows 对应的本机翻译方案。

## 3. 外观对齐基准

字号定义和比例以 [CandidatePreferences.swift](https://github.com/jizw0704-source/lingomate/blob/a599b738bef28662ae92d975b8ad3dd33b3f7306/native-macos/Sources/CandidatePreferences.swift) 为准：16、18、20、22，默认 18，相关字体按 `size / 18` 缩放。Windows 要核对实际绘制尺寸，不能只核对菜单显示值。

候选布局以 [CandidatePanel.swift](https://github.com/jizw0704-source/lingomate/blob/a599b738bef28662ae92d975b8ad3dd33b3f7306/native-macos/Sources/CandidatePanel.swift) 为准：短词中文基准 18、英文 12、编号 11；长行中文 16、英文 14、编号 13；词性 11，均按字号比例缩放。单页顶栏显示拼音、展开／收起和齿轮，多页增加翻页与页码。短词选中中文使用反色紧凑胶囊，英文与词性保留自身层级。README 中关于可见“模式”标签的措辞与该渲染实现有差异，保留这条核对备注。

颜色、圆角与按钮样式分别参考 [NativeTheme.swift](https://github.com/jizw0704-source/lingomate/blob/a599b738bef28662ae92d975b8ad3dd33b3f7306/native-macos/Sources/NativeTheme.swift) 和 [ActionButton.swift](https://github.com/jizw0704-source/lingomate/blob/a599b738bef28662ae92d975b8ad3dd33b3f7306/native-macos/Sources/ActionButton.swift)。使用中性浅深背景、绿色英文和次要灰色词性，保留系统字体回退与至少 44 的逻辑点击区域；Windows 做实际 DPI 换算，不把 Mac 点数直接当作物理像素。

统一设置的实际页序以 [SettingsWindow.swift](https://github.com/jizw0704-source/lingomate/blob/a599b738bef28662ae92d975b8ad3dd33b3f7306/native-macos/Sources/SettingsWindow.swift) 为准：账号、翻译、输入、外观、学习。候选窗和系统菜单打开同一设置界面。需要服务确认的控件，在连接或回读失败时显示对应状态；不能仅凭控件勾选就提示应用成功。

建议用同一组测试内容收集双方界面：短词、长词、多译法、翻页、无候选、引擎故障、翻译等待与失败、五页设置。Windows 另覆盖 100%/125%/150%/200% 缩放、窄工作区和跨屏移动。先按逻辑布局比较，再检查字体回退带来的差异。预览截图和真实宿主截图分别标识。

## 4. API 设置与 AI 翻译实施范围

参考 [AISettingsWindow.swift](https://github.com/jizw0704-source/lingomate/blob/a599b738bef28662ae92d975b8ad3dd33b3f7306/native-macos/Sources/AISettingsWindow.swift) 和 [AITranslation.swift](https://github.com/jizw0704-source/lingomate/blob/a599b738bef28662ae92d975b8ad3dd33b3f7306/native-macos/Sources/AITranslation.swift)。下列项目全部属于后续 Windows 功能对齐范围，当前尚未实现。

| 项目 | Windows 必须提供的行为 |
| --- | --- |
| 设置入口与字段 | 在统一设置的“翻译”页及相应菜单入口配置完整接口地址、模型名、API 密钥；控件、文案和状态按 Mac 对齐 |
| 预设与自定义 | 提供 MiniMax 国内／国际预设，允许修改符合当前 Chat Completions 请求格式的地址与模型；完整地址须校验，其他服务兼容性另验。当前参考模型为 `MiniMax-M2.7-highspeed`，仅是代码预设 |
| 启用与关闭 | 首次默认关闭；预设按钮只填字段；“保存并启用 AI”保存并启用，但保存动作不发测试请求；“使用本机翻译”关闭在线请求并保留已存密钥 |
| 凭据 | Windows 使用本机安全凭据存储，由设置／翻译辅助进程访问，按完整接口地址隔离；密钥留空只复用该地址已保存的值。密钥不进入普通配置、日志或进程参数 |
| 在线请求 | 用户主动启用后，无离线释义的当前候选满足长度条件（普通至少 3 字、个人候选至少 2 字）时，停顿约 850 ms 请求翻译；只取完整最终译文。普通输入回调不等待网络 |
| 候选与状态 | 展示等待、就绪、失败及重试；等待／失败时中文仍可选，未完成英文不能提交；整句译文不附词性、不加入单词学习。提交仍须通过真实引擎验证候选并消费对应拼音 |
| 请求失效 | 拼音、候选、页码、组合上下文或配置改变，以及取消、提交、关闭在线功能时，使对应旧请求和结果失效；旧响应不能串入新候选或新宿主 |
| 本机回切 | 提供明确的本机翻译入口；本机能力或资源未就绪时显示真实状态和准备方式。离线词语释义、离线整句翻译、在线 AI 三者分别验收 |

功能授权沿用当前隐私约束：只发送当前中文候选及固定翻译指令，不发送原始拼音、宿主正文、剪贴板、个人词库文件或输入历史。账号同步不包含句子。Mac 真实 MiniMax 请求质量与速度仍待验收；Windows 也需单独取得真实服务结果。

新增 AI 验收项全部待实施后执行：

| 编号 | 操作及验收重点 |
| --- | --- |
| AI-01 | 隔离新配置默认关闭；点击预设、填写字段、保存及重开设置，分别核对字段、启用状态和网络请求次数 |
| AI-02 | 首次保存无密钥报错；同地址留空保留密钥；换地址不复用其他地址密钥；关闭 AI 后不发请求 |
| AI-03 | 用合成候选验证触发条件、等待状态和中文提交；连续修改只允许当前结果显示，不能逐键发请求 |
| AI-04 | 模拟权限失败、额度限制、超时、网络中断及无效响应；状态明确、中文可用、未完成英文不可提交，可重试或回切 |
| AI-05 | 请求期间切换候选、分页、取消、失焦、改模型或关闭 AI，再返回旧响应；确认没有旧译文显示或误提交 |
| AI-06 | 就绪译文经点击与 Shift＋空格提交一次；剩余拼音继续处理；没有词性或单词学习记录混入 |
| AI-07 | 普通宿主与包内宿主使用同一用户配置时核对设置与凭据隔离规则；模拟检查通过后再由用户启用真实服务验收 |

## 6. 功能和默认行为核对方式

## 7. Claude 修复交接与可用基线

接收版本、最终 diff、构建来源、安装包和 DLL 摘要、安装位置、包身份、当前已验证应用及剩余问题。旧的 `WINDOWS-CLAUDE-HANDOFF-2026-10-13.md` 是发现包视图问题前的交接，不把其中旧失败表当作当前状态。

当前关键背景是 Claude 已报告将 0.1.16 放到真实用户位置，修复登记并通过包外 COM 加载。它补齐了系统前提，仍需最终包的真实键盘结果。接手验收分开记录：

1. **包外文件和登记。** 独立且无包身份的观察进程确认真实位置、摘要与登记指向。
2. **模块与系统输入路径。** COM 加载和 Windows 实际 profile 激活分别验证；自有夹具直接调用成功不能证明普通应用的系统路径。
3. **真实键盘。** 用户在 Chrome、钉钉、grokbot、Codex／用户所称 ChatGPT 应用中执行共同用例，记录应用版本和实际加载版本。切换器名称不算输入成功。

Windows 搜索等现代宿主另记录兼容进度；需要实际实现对应接口和设备验收，不能仅登记能力，也不能把普通应用失败一概归因于现代宿主要求。

## 8. 稳定性与优化准备

优先保住可用基线，随后按功能和外观差距推进；优化以测量和回归结果为依据。

| 工作项 | 后续检查重点 | 证据要求 |
| --- | --- | --- |
| 安装进程包身份保护 | 公开脚本、显式安装路径、底层登记、UAC helper、卸载和回退均在副作用前检查 | 模拟测试和实际包身份检查分开；最终交付包必须包含保护。当前源码默认路径检查不能推断全部底层入口已经覆盖 |
| 跨宿主存储 | 个人记忆、学习和配置在包内／包外的路径解析、并发、原子保存、损坏处理 | 先用合成临时数据；真实包内旧数据迁移另写预览、冲突、备份和恢复方案 |
| 编辑正确性 | 每次输出一次、写入原文档、过期候选拒绝、失焦与终止不串到新上下文、实际编辑成功后才确认记忆 | 自有 TSF 夹具加真实应用；保留 FIFO、epoch 和提交回执约束 |
| 候选稳定性 | 鼠标移入移出、点击、滚动、展开、DPI 和主题切换，消息、重绘与 GDI 资源是否稳定 | 合成内容；保留 hover 修复，不引入焦点抢占或打字动画 |
| 输入延迟 | 冷启动、热输入、查询到候选、提交延迟及队列压力 | 自有宿主记录无内容计时和 P50/P95/P99；测量后制定阈值，不预设线程或队列改法 |
| 更新与恢复 | 取消权限提升、损坏包、部分登记失败、旧版恢复，以及已运行宿主驻留旧 DLL 的情况 | 保留旧版本和个人记录；文件、登记、加载与键盘分层验证 |

上述均为后续工作，不是本轮测试结果。生产诊断不新增逐键日志或输入内容采集。
