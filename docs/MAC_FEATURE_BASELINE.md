## 借词取字与词库管理整合参考 · 0.12.13 开发版

Mac 本轮将借词取字与 0.12.12 个人词库管理整合。对照用例：确认“灵活”后退格删“活”，确认“果实”后退格删“实”，再以无待选拼音的空格结束；随后按 `lingguo` 召回“灵果”，在词库页搜索、优先／取消和删除，重载后检查结果。多音字保留原词音节；选区删除只限本轮确认的范围，未知新词仍遵循 2–6 字过滤，已有词与跟踪最多 16 字。

源码为 `WordEditState.swift`、`InputController.swift`、`EngineClient.swift`、`Models.swift`、共享 `edited_word.rs`／`lib.rs` 和原有词库管理文件。共享确认请求通过可选 `track_edits: true` 返回一次性的 `editToken`；确认宿主删除后发送 `edit-memory`（`learning_token`、`edit_start`、`edit_length`），结束时发送 `finish-memory`（`learning_token`）。两种操作均要求空 `input`、正确会话与引擎代际；删除会轮换令牌，全删返回空令牌并结束，取消后旧令牌无效。只使用候选的原音节，不接受宿主正文或任意新词作为请求参数。

默认请求不新增 `editToken`；TSF 的 `deferred_output` 回执不启用此跟踪，既有 Windows 行为保留。Windows 尚未实现借词取字：需在其原生客户端独立验证删除成功、UTF-16 位置及会话边界，再明确接入；不能将 Mac 选区模型或共享编译检查算作 TSF 功能完成。来源和存储格式不变，详细规则与测试边界见 [Mac 使用指南](../native-macos/README.md#借词取字记忆--mac-01213-开发版)及 [QA](../native-macos/QA.md#借词取字与个人词库整合-2026-10-14)。

## 输入与候选功能

### 新增开发功能：固定表达联想

Mac 开发代码显式启用共享桥接 `--fixed-expressions`，打包 `fixed-expressions.json` 和 `EXPRESSIONS-NOTICE.md`。当前未包含于此前安装包，Windows 和网页仍保持默认未启用，不因共享代码更新自动改变行为。Windows 接入时需要同时生成并分发这两份资源、保留归属许可并显式传入该选项，之后做 TSF 真实键盘与确认回执验收。

对照用例：输入 `chiputao` 后仍有普通候选，并可选“吃葡萄不吐葡萄皮”；选中后整句上屏、拼音清空，成功确认后才保存前缀及完整读音，重启后可再次召回。取消、暂停记忆、伪造读音和错误译法不得保存；`kaifazhe` 选“开发”后仍保留 `zhe`。单音节、缩写、未完成音节与额外尾随拼音不触发该整句补全，空格仍按普通首选中文处理。完整来源和验证范围见 [Mac QA](../native-macos/QA.md#固定表达联想-2026-10-13)。

**新增开发代码（尚未进入此前安装包）：英文片段首字母大写。** 默认开启，中文模式回车确认英文及选择英文译词时，将当前片段首字母大写，后续英文词保持原样。已有大小写、技术字面量保留，英文直输不变；设置中可关闭并持久化。Windows 对照用例：`wo`＋空格 → `hello`＋回车 → 空格 → `world`＋回车得到“我Hello world”；随后确认中文再输入 `hello`＋回车应输出 `Hello`；关闭后应保留 `hello`，`AI`／`iPhone` 保持原样。只记录 Mac 独立代码与隔离检查完成，Windows 接入和双端实机测试待验证。源码为 `EnglishFragments.swift`、`InputController.swift`、`SettingsInput.swift` 与 `SettingsWindow.swift`；范围见 [新增验收记录](../native-macos/QA.md#英文片段首字母大写-2026-10-13)。以下表格保留已安装 0.12.9 的基线行为。

## 排序与个人记忆

| 功能 | Mac 规则 |
| --- | --- |
| 基础排序 | 完整原样词匹配优先，结合固定词频与项目日常先验；同音歧义仍需用户选择，不使用宿主前文或上下文语言模型 |
| 选词记忆 | 默认开启；确认中文或选择其英文释义后，记忆对应中文及读音；输入拼音、浏览、取消和原样字母不产生记忆 |
| 记忆加权 | 相同读音与拼音消费范围内竞争，避免短词挤掉完整词句；次数加分按最多 20 次计算，并按后续确认选词数衰减，256 次后回到基础排序；词条保留，重新选择刷新优先级 |
| 一次拼音分段组词 | 同一组合中分次确认中文片段可合成新词；修改、取消、焦点变化或原样提交中断合成，英文输出不参与中文拼接 |
| 连续逐字组词 | 例如分别确认“钙”“钛”“矿”，再输入 `gaitaikuang`；已有词按实际读音识别，最长 16 字；未知组合自动尝试保存 2–6 字短词，允许偶尔误记 |
| 逐字组词边界 | 确认间隔超过 20 秒，或英文、标点、取消、删除、光标／鼠标及焦点变化结束组合；不读取宿主正文来拼词 |
| 暂停与存储 | 暂停只停止新增记忆，已存词仍参与排序；每词最多 16 字、最多 5,000 条拼音映射。损坏文件保留并暂停写入，保存失败不撤回已输出文字 |

未知短词识别可能保存前缀或误记短语，不保证完整分词。两类组词流程应分别验收。个人词库位于 `~/Library/Application Support/BilingualCompanion/PersonalVocabulary/words.json`，只保存词条、拼音、聚合次数及选择次序，不保存逐次输入历史，也不上传。

## 学习记录与账号

**本地单词学习无需登录。** 确认输出词表英文候选后，保存英文、对应中文、词性、累计选用次数及手动掌握状态。浏览、取消、中文确认、原样字母、英文直输和整句译文不计入；“已学习”仅表示发生选用，不表示已掌握。

本地页提供搜索、全部／已学习／已掌握筛选、标记掌握与重新学习、删除及 UTF-8 CSV 导出。最多 5,000 个词条，CSV 防止电子表格公式注入。文件位于 `~/Library/Application Support/BilingualCompanion/LocalWords/words.json`，与个人中文词库和账号缓存独立，不自动上传或迁移。损坏／超限文件保留并报告错误，不自动清空。

**在线账号尚未上线。** Mac 已实现自建邮箱验证码客户端及所选词条同步，但公网服务、域名和 SMTP 发信尚未配置，真实收信、登录和跨设备同步待验证。短信登录未实现。部署后同步范围仅为词表英文、对应中文、词性、次数及掌握状态；不包含句子、原始拼音、个人中文词库或宿主正文。本地页的掌握和删除不改变云端记录。Windows 账号功能另建同步任务，不作为现有本地学习的前置条件。

## 整句翻译

| 路径 | 已实现行为 | 当前条件与限制 |
| --- | --- | --- |
| 离线词语释义 | 中文候选查询本地释义，展开可选译法 | 使用固定词典，不读取前文；不是上下文整句翻译 |
| Apple 本机整句翻译 | 无离线释义的当前候选满足长度阈值后，停顿约 350 ms 请求翻译；一般阈值为 3 个中文字，个人词库候选为 2 个 | macOS 26+ 和中英文语言资源；每个整句候选一种译文。Windows 需另选实现方式，Apple 接口不能直接移植 |
| MiniMax 在线翻译 | 主动启用后，无离线释义的较长候选停顿约 850 ms 请求；只展示最终译文，失败保留中文并可重试／主动切回本机 | 需要网络、有效接口与密钥；真实请求速度、质量和费用未验收。当前配置预设模型不代表账号必然有访问权限 |

继续输入、切换候选／页码、取消或提交会使旧翻译结果失效，设置变化同样使旧请求和结果失效。未完成译文不能提交，中文选择仍可用。整句译文不强行标注词性，不加入本地或账号单词学习记录，当前没有整句多译法。

MiniMax 仅发送当前中文候选与固定翻译指令，不发送原始拼音、宿主前文、个人词库或输入历史。密钥由辅助进程访问系统钥匙串，按完整接口地址隔离，不进入日志、参数、配置 JSON、仓库或 Obsidian；Windows 需采用自身安全凭据存储。说明见 [翻译与隐私](../native-macos/README.md#翻译与隐私)。

## 安装更新与维护

Mac 已提供 DMG 和原生安装器，安装位置为当前用户的 `~/Library/Input Methods/BilingualCompanion.app`。替换前检查运行状态、校验应用身份与签名并保存旧版备份；拒绝覆盖正在使用的输入服务和无关应用。更新或恢复不删除个人词库、学习记录与配置，也不自动关闭宿主、注销或重启电脑。

更新器已实现版本检查、下载取消、大小与 SHA-256 校验、ZIP 路径／身份／版本／芯片检查、签名与系统安全评估、确认安装和旧版恢复。**远程更新清单仍为 `unpublished`**，草稿附件不会触发更新；正式发行签名、公证和实际远程升级／回退尚待完成。Windows 使用自己的安装与更新实现，复用校验、确认和恢复原则。

只读诊断仅提供版本、会话计数及状态布尔值；引擎故障有超时与恢复边界，普通服务防止重复实例。服务运行、登记或窗口预览正常不等于宿主已接受输入。历史试用曾出现已打开应用在更新后无响应、重启该应用后恢复，根因和长期稳定性仍需跟踪。

独立开发预览关闭主窗口、Command-Q 或达到预览时限后，会收起该进程的全部浮窗并退出；默认 300 秒，可设置 1–900 秒。此时限不用于正常输入服务或日常设置窗口，避免再次遗留“字号预览”等浮窗。

## 表情与符号候选 · Mac 0.12.14 开发版

中文模式输入完整关键词，可选择本地表情或符号：`zan`／`dianzan` → 👍，`yumaoqiu` → 🏸，`shengluehao` → ……／…，`zuojiantou` → ←／`<--`／⇐，`alpha`／`aerfa` → α／Α。另含常用运动、情绪、箭头、数学符号和 24 组希腊字母名称；大小写不影响匹配，支持完整分音拼音。仅精确关键词触发，简拼、未完成音节、前缀或混合长句不触发。

保留原引擎前两项普通候选和其余普通候选的相对顺序，每次最多补充三项，总数最多 64，页码按实际候选数计算。正常空格仍确认第一项；回车仍执行原来的英文原样确认／片段大写规则，不会自动替换为符号；Shift 英文直输不经过该功能。菜单“表情与符号候选”默认开启，可关闭并保存，下次查询生效。

符号经当前完整输入重新核对后直接上屏、消费本次输入，不发送 AI 翻译、不给出英文译词，不确认中文记忆回执、不新增英文学习记录，并结束当前逐字／借词取字组合。取消、浏览不产生记录。已有普通中文提交、实际读音与个人词库格式保留。映射由项目独立整理，代码中的 Unicode 字符是输出文本；不下载或分发第三方表情图像、字体或新词频数据，字形由接收应用及系统提供。

本功能只改 Mac 展示、选择与本机偏好，共享 Rust、C ABI、词库和请求字段未更改。Windows 需显式实现候选注入、字面量确认、记忆边界与开关，不能通过拉取 Main 自动启用。依赖尚未合并的 PR #12、#17；整合最新 Main `5c5be3c`，保留 Wright 的 Windows 0.1.21 及共享数据构建修复。未安装、未合并、未制作安装包或发布更新；真实键盘跨应用验收待后续试用。
