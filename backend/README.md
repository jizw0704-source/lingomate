# 自建账号服务 · 邮箱验证码

这是0.9的独立服务端：邮箱验证码注册/登录、会话续期、按账号保存单词及手动掌握标记。使用 Python 3.11+ 标准库、SQLite 和安全 SMTP，没有新增生产依赖。当前只实现邮箱，手机号验证码需要接入短信服务后另行开发。

**目前验证隔离协议、慢发信并发和临时数据库，没有部署公网服务或发送真实邮件。** 可安装的 Linux/systemd 服务及 Caddy 模板见[部署包](deploy/README.md)；配置已通过Linux单元校验和Caddy校验，但缺少真实服务器、域名与邮件配置，不能真实登录。 客户端未配置服务时会明确显示“账号服务尚未连接”，不会生成假账号或假登录成功。

## 检查

在仓库根目录运行：

```sh
runtime/python/bin/ruff format --check backend
runtime/python/bin/ruff check backend
runtime/python/bin/python -m unittest discover -s backend -v
runtime/python/bin/python -m compileall -q backend
```

七项测试使用临时目录、测试邮箱和内存发信替身，包含真实本地 HTTP 请求；不访问系统钥匙串或用户学习数据。

## 部署

1. 准备一台运行 Python 3.11+ 的服务器、账号服务域名和能够发信的 SMTP 邮箱。将本目录放在专用非管理员服务用户拥有的目录中。
2. 通过服务管理器或权限为0600的环境文件设置下表。密码留在服务器，不写入仓库，不交给聊天或同步到笔记。
3. 以服务用户运行 `python backend/server.py --state /var/lib/bilingual-account --port 9057`。服务只监听127.0.0.1；前端必须提供有效证书的 HTTPS，不直接公开9057端口。
4. 用 Caddy、Nginx 等反向代理把域名转发到本机9057。下面是 Caddy 的配置模板，替换为自己已准备的域名后使用；证书与代理部署未在本轮验收。
5. 原生候选窗或输入源菜单 → 设置 → 账号与学习 → 高级设置，填入 `https://你的账号域名` → 保存。然后发送邮箱验证码、填写收到的六位验证码、验证登录。

| 环境变量 | 用途 |
|---|---|
| `IME_SMTP_HOST` | SMTP 服务器 |
| `IME_SMTP_PORT` | 默认STARTTLS587 / SSL465 |
| `IME_SMTP_MODE` | `starttls` 或 `ssl`，强制TLS证书验证 |
| `IME_SMTP_USER` | 邮箱服务要求认证时的用户名 |
| `IME_SMTP_PASSWORD` | 仅在服务器环境中配置 |
| `IME_MAIL_FROM` | 服务商允许使用的发件地址 |

```caddyfile
account.example.com {
    request_body {
        max_size 1MB
    }
    reverse_proxy 127.0.0.1:9057
}
```

独立服务管理器须设置自动重启、正确工作目录和上述环境；测试后的 `GET /health` 应返回 `{"ok": true}`，这只证明进程运行，不证明邮件已送达。健康检查不发邮件。不要为排错关闭HTTPS或TLS验证；代理不得把请求正文、验证码、Authorization、邮件地址写入访问日志。

## 上线验收

- 用自己控制的两个测试邮箱分别收取验证码，检查无效、过期和重复验证码；接收失败须检查服务商SMTP、发信额度、域名SPF/DKIM和垃圾邮件规则。
- 在第一台设备选择 `xuexi` 的 `learn`；学习页新增单词，选用次数增加。手动标记掌握并同步；第二台设备使用同一邮箱和同一服务地址登录后应看到记录。
- 用另一邮箱登录应看到另一份记录；退出后输入不会继续写入此前账号。跨设备同步、实际邮件、Keychain保存和物理键盘提交均需真实验收。
- 临时断网后确认待同步操作保留；重新联网点同步，重复请求不能重复增加次数。掌握标记按服务端接收顺序处理，最后接收的操作生效；没有跨设备编辑冲突合并或找回被撤销的历史标记功能。

## 数据与协议

客户端在成功提交词表英文后才记录英文词语、对应中文、词性和使用次数。账号同步不上传整句、拼音、个人中文词库、正文或剪贴板。学习账号与原先的本机选词记忆分开；未登录仍可使用输入法。掌握由用户标记，不由使用一次自动推断。

SQLite保存在`--state`专用目录（0700）；数据库和随机OTP摘要密钥文件为0600。服务器存储邮箱、单词、使用次数、掌握标记、事件去重ID、会话令牌摘要和短期验证码摘要；验证码不明文入库、单次有效10分钟、最多5次验证，60秒邮箱发送间隔、每邮箱每小时10次、每IP每小时60次。仅信任本机代理提供的原始IP，部署代理应覆盖外部伪造的X-Forwarded-For。

访问令牌有效15分钟，续期令牌30天，每次续期旋转。客户端凭据存系统钥匙串，本地缓存不包含访问/续期令牌。续期响应丢失需要重新登录；不声称支持多设备全部退出、账号删除、短信、邮箱改绑或数据导出。服务端事件去重记录需要保留以避免离线重试被重复计数；不能随意删除。部署者应安排加密备份、磁盘容量监控及数据保留策略；这是实验服务，尚未负载或独立安全审计。

| 请求 | 返回 |
|---|---|
| `POST /v1/auth/code`，email | SMTP接受后的sent；不返回验证码 |
| `POST /v1/auth/verify`，email/code | access_token、refresh_token、expires_in、user(id/email) |
| `POST /v1/auth/refresh`，refresh_token | 旋转后的同账号凭据 |
| `POST /v1/auth/logout`，Bearer及refresh_token | 撤销匹配的本次会话 |
| `GET /v1/words`，Bearer | 仅当前账号单词列表 |
| `POST /v1/events`，Bearer及事件数组 | 已确认事件UUID；账号由服务端令牌决定 |

没有显示验证码的开发端点、明文HTTP客户端登录降级或账号模拟开关。公网部署和邮件通道配置仍待提供资源后继续。

发信网络等待不持有数据库全局锁，其他账号可继续同步。发信失败也会计入限流额度，同一邮箱至少间隔60秒重试；只有发信成功后验证码才可使用。
