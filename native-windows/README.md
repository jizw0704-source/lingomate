## 外观、字号、标点与系统图标 · 0.1.9

候选窗点击“设置”，或按 Ctrl＋Shift＋P，选择“外观”“候选字号”“标点规则（当前应用）”。默认浅色、18 号、自动标点；外观和字号保存至 `HKCU\Software\LingoMate\Candidates`，在其他应用激活输入法时加载，标点规则仅作用于当前应用会话。更改外观或字号保留拼音、候选页及当前译法；学习记录和更新窗口也跟随外观，系统高对比度优先。

中文候选后使用中文标点，英文候选及回车确认字母后使用英文标点；可固定为中文或英文。支持配对引号 `“”`／`‘’`、括号 `（）`／`【】`、书名号 `《》` 及顿号 `、`。拼音中的单引号仍用于分隔音节。数字的小数点、时间冒号和日期斜杠默认保留半角；输入 `https:`、`www.` 或邮箱 `@` 后保留连续地址字符，空格结束地址输入。原样字母按回车后恢复拼音组合。数字保护在固定中文模式下按中文规则，网址／邮箱保护始终生效。此功能仅根据本输入法处理过的字符判断，不读取或推断粘贴文本、宿主正文或光标前的文本。

字号档位为 16／18／20／22，使用系统 Microsoft YaHei UI 及系统字形回退，不分发第三方字体。候选按显示器 DPI 缩放，窄幅布局可换行，点击区域与绘制使用同一套布局；仍保持每页五项和原有编号。输入源采用 DLL 内嵌“果”字图标，包含多种尺寸，无额外安装图标文件。以上是已实现的客户端功能，Windows 11 实体键盘、系统主题切换、多屏、高对比度及输入源图标展示须由 Wright 在实机核对。

## 候选空白与恢复 · 2026-10-12 本地修复

Windows 0.1.8 本机试用中出现仅有工具栏、没有候选文字的窗口。旧版零候选窗口宽度不足，导致引擎异常提示完全被裁掉；0.1.8 修复保持 560 px 宽度，并在候选区域显示“引擎暂不可用”或“未找到候选”，提示回车可提交原样字母。错误状态不再绘制旧候选。

引擎的第一条响应允许 1,500 ms（包括首次取消请求），之后仍为 500 ms。失败后保留当前字母，连续输入不会反复延后两秒重试时点；重新连接后，选择、译法和分页操作先查询保留的拼音。引擎启动失败的具体原因尚未在真实聊天宿主内确认。

本机已通过编译、24 项原生 Rust 检查及 8 种原生 HWND 绘制检查，并安装到新的独立版本目录，旧目录保留。用户已确认原版在记事本输入 `wo` 可输出“我”。修复包安装后，原聊天进程一度持有旧 DLL；后续检查已确认重新打开的聊天进程加载新 DLL，但候选实际输入验收尚未完成。升级后仍须保存工作并完整退出／重新打开宿主应用；安装操作不自动关闭宿主、重启输入服务或更改输入源。详细边界见 [验证记录](QA.md#2026-10-12windows-候选空白本机修复)。

该次本地修复仍标为 0.1.8，未替换内部草稿附件或公开发布。普通安装 EXE 的 TSF 登记出现异常且返回成功退出码，本机最终使用同一用户提升权限运行可信安装核心完成登记；不能据此认定普通安装 EXE 已通过验收。

## 连续逐字组词记忆 · 0.1.8

连续分别输入并确认“钙”“钛”“矿”后，再输入完整拼音 `gaitaikuang`，可优先选择已记忆的“钙钛矿”。

已有词按汉字及实际选用读音识别，最长 16 字；未知组合自动尝试保存 2–6 字短词，过滤常见虚词。确认间隔超过 20 秒，或输入英文、标点、取消、删除、移动光标及切换输入框时结束组合。未知短词识别可能保存前缀或误记短语，不保证完整分词。 候选窗设置（或 Ctrl＋Shift＋P）中的“中文选词记忆（当前应用）”可暂停本应用的写入，已保存词条保留。

个人词库只保存词条、拼音、累计次数和使用次序统计，不读取宿主正文或剪贴板，不保存逐次输入历史，不上传。沿用许可明确的词库与词频，没有新增语料、模型或生产依赖。 位置为 `%LOCALAPPDATA%\LingoMate\PersonalVocabulary\words.json`，与英文学习记录独立。多个应用共享本机词库，失败输出不记忆。

Mac **0.12.9 / build 31** 与 Windows **0.1.8** 安装包、校验文件、对应源码及试用说明已上传[内部试用草稿](https://github.com/jizw0704-source/lingomate/releases/tag/untagged-e25b2e907874382cdb4a)并完成下载回校验；草稿仅维护者可见，须下载后转交同事。未公开发布或启用远程更新清单。本机已安装 Mac 0.12.9，用户已确认 Codex 中已知词与新组合“钙钛镍”的逐字输入及靠前整词候选；整词提交、重启保留、跨应用与 Windows 实机仍待验收。

Windows 版本采用系统原生 Text Services Framework（TSF，文本服务框架），由 Rust 文本服务 DLL 接入应用输入框，并通过独立本地进程调用现有拼音与英文释义引擎。

## 本地单词学习

0.1.6 的[原生构建、隔离学习窗口及安装器检查](https://github.com/jizw0704-source/lingomate/actions/runs/38151744083)已通过，Windows 11 实体键盘计数与真实安装仍待验收；该开发阶段维护者草稿安装包为 0.1.4。

本地单词学习已接入 Mac 0.12.5 / build 27 与 Windows 0.1.6，无需登录。确认输出词表英文候选后，保存英文、对应中文、词性、累计选用次数及手动掌握状态；浏览、取消、中文确认、原样字母、英文直输及整句译文不计入。提供搜索、全部／已学习／已掌握筛选、掌握与重新学习、单词删除和 CSV 导出。记录与账号缓存分离，不自动上传或迁移；Mac 已登录账号的选词同步仍按原规则进行，本地页的掌握／删除不改变云端记录；“已学习”仅表示选用，不代表掌握。

Mac 从输入源菜单“本地学习记录…”或“设置 → 学习”进入；Windows 从候选窗设置（或 Ctrl＋Shift＋P）选择“本地学习记录…”。窗口可单独关闭，正常候选仍不抢宿主键盘焦点。文件位置为 Mac 的 `~/Library/Application Support/BilingualCompanion/LocalWords/words.json` 和 Windows 的 `%LOCALAPPDATA%\LingoMate\LocalWords\words.json`；每份文件最多 5,000 个词条，只保存聚合元数据，不保存正文、剪贴板、原始拼音或时间顺序输入历史。

两端采用跨进程文件锁及原子替换；损坏或超限文件保留并报告错误，不自动清空。Windows 在异步宿主编辑成功后记录，存储工作在后台执行，并将已加载模块保留至宿主退出，避免后台线程退出时的卸载竞争；升级后需重新打开宿主应用；保存失败不会撤销已输入文本。导出包含全部本地词条，使用 UTF-8 CSV 并防止电子表格公式注入。删除后，再次确认输出该词会重新建档。

## 英文词性设置

在候选窗顶部点击 **设置**，勾选或取消“显示词性”；也可按 **Ctrl＋Shift＋P** 打开此菜单。开关同时控制主要英文候选与展开译法，并保存至当前用户的 `HKCU\Software\LingoMate\Candidates`，重启后保留；切回已有输入会话时重新读取。此快捷键不切换标点，与 Mac 的同名快捷键用途不同。

默认显示 `n.`、`v.`、`adj.`、`adv.` 等缩写，多词性可显示为 `n./v.`。词性来自既有人工用法和固定 WordNet 3.0 索引，完整词无法核对时不标注。它仅为学习提示，不判断整句语法，也不改变提交英文。见 [词性来源与许可](../docs/THIRD_PARTY.md#英文词性来源)。

## 构建与检查

Windows 日常开发使用 `codex/windows-dev` 分支，相关修改通过 Pull Request 请求合并到 `main`。每次提交只包含当前任务的改动，并记录自动检查与 Windows 实机验证范围；PR 合并后同步最新 `origin/main`。完整流程见 [协作维护说明](../CONTRIBUTING.md#开发与合并)。

面向同事的安装形式为安装 EXE，使用 Inno Setup 6 构建，详见 [安装包与同事试用](../docs/PACKAGING.md#windows-构建与安装)。安装器沿用当前用户目录与文件校验流程，保留历史版本；已上传维护者 Release 草稿，尚未提供公开下载。引擎 EXE 与安装 EXE 是不同文件。

准备 Windows 64 位 PowerShell、Git、Rustup、Python 3.10+，以及带 MSVC 与 Windows SDK 的 Visual Studio C++ 构建工具。执行：

```powershell
git clone https://github.com/jizw0704-source/lingomate.git
cd lingomate
./native-windows/tools/setup.ps1
./native-windows/tools/build.ps1
./native-windows/tools/check.ps1
```

准备脚本使用 Rust 1.96.0 与固定上游快照，发现已有源码改动时停止并保留文件。构建产物位于 `native-windows/package/windows-x64/`，包括 DLL、共享引擎、数据与来源说明。构建和检查不会安装或选择输入法。

仓库的 Windows 检查流程执行 MSVC 构建、PowerShell 语法检查、Rust 格式与 Clippy、真实引擎回归及 DLL 类厂生命周期检查。流程不登记系统输入源，也不发布完整数据或安装包。检查结果见 [验证记录](QA.md)。

## 安装与使用

在 Windows 机器完成检查后运行：

```powershell
./native-windows/tools/install.ps1
```

安装脚本校验文件，将新版本放入 `%LOCALAPPDATA%\\LingoMate\\Windows\\` 的独立目录，并登记本项目的 COM 类与中文输入配置。旧版本文件保留，登记失败时尝试恢复原登记。部分系统的 TSF 登记可能需要相应权限；本阶段安装与权限行为仍待实机验证。

完成后通过 Windows 输入切换器手动选择“灵果 · LingoMate”。如系统要求添加中文语言或重新登录，按系统提示处理；脚本不自动重启、注销、切换输入法或关闭其他应用。

| 操作 | 功能 |
| --- | --- |
| 空格 / 数字 1–5 | 确认当前页中文 |
| Shift＋空格 | 确认当前选中的英文译法 |
| Enter | 有组合输入时提交原样字母；空回车由当前应用处理 |
| Tab / Shift＋Tab | 展开及切换译法 |
| ↑ / ↓ | 切换当前页候选 |
| PageUp / PageDown，`-` / `=` | 翻页 |
| Esc | 收起译法，再取消输入 |
| 单按并松开 Shift | 切换中文 / 英文直输 |
| 候选窗“更新” / Ctrl＋Shift＋U | 打开独立软件更新窗口 |

## 远程版本更新

完成 0.1.1 或后续版本的首次安装后，可点击候选窗口的“更新”，或在灵果处于活动状态时按 Ctrl＋Shift＋U，打开“软件更新”。首次安装可使用维护者提供的安装 EXE，也可自行构建；0.1.0 不含更新程序，需要先手动升级一次。

窗口依次提供检查、更新说明、下载校验和确认安装。每日自动检查默认关闭，可在窗口中开启；启用后，在灵果激活且距上次检查超过 24 小时时检查，仅发现新版本时显示窗口，不自动下载或安装。网络失败不影响输入，可手动重试。

新版本安装至独立目录。校验失败不会登记新版本，登记失败会尝试恢复原登记；若恢复也失败，界面明确报告。更新完成后，请切换到其他输入法，保存工作并重新打开使用灵果的应用，再选择灵果。窗口可“恢复上一版本”，回退后同样需要重新打开应用。程序不强制关闭应用、重启输入服务或重新登录。

更新来源固定为本项目 GitHub Releases，不需要账号或 API 密钥。检查和下载由独立桌面进程执行，不在 TSF 按键回调中进行网络请求，也不发送输入内容、学习记录或账号信息。公司网络连通性及 PowerShell 运行策略需实机验证。

当前尚未公开发布 Windows 更新包；新词库已改用许可明确来源，开放下载仍需完成实机验收、发行签名及对应源码交付。更新使用 HTTPS 发布源及 SHA-256 校验，不代表已完成 Windows 发行签名。详见 [Windows 更新与发布](UPDATES.md)。

## 数据、依赖与验证边界

Windows 客户端不读取宿主正文、选区或剪贴板，不保存输入日志，也不调用在线翻译或账号服务。只将当前拼音及已选择候选通过本机管道交给共享引擎；文字不作为进程参数。首版不启用个人词库，避免不同应用进程并发覆盖同一文件。

Windows 平台接口使用 Microsoft `windows` / `windows-core` Rust 绑定；JSON 协议复用既有 serde 与 serde_json。平台绑定只在 Windows 编译，新增依赖用于系统接口接入。代码采用 GPL-3.0-or-later，当前词库与改编数据为 CC BY-SA 4.0，来源及旧版审计见 [第三方来源](../docs/THIRD_PARTY.md)。

macOS 上的 Windows 目标类型检查与引擎回归不等同于 Windows 实机输入验收。当前尚未发布正式 Windows 安装包，系统登记、应用兼容性、候选焦点、Shift 实际事件、缩放及长期稳定性仍待验证。
