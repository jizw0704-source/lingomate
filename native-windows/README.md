## 输入边界与更新／同步修复 · 0.1.22 · 2026-10-15

- **输入不丢字符**：组合输入中未用作候选编号的数字和受支持的 Shift 符号按 FIFO 处理，先保留原拼音再输出字符。将方向键、Delete 等交还宿主前结束自有组合边界；外部文本或光标变化使迟到的旧候选编辑失效，避免覆盖宿主新插入的内容。引擎尚未回复时按原拼音保留；拒锁或拒写时结束旧组合，并为后续输入创建新文档对象。只观察组合范围和光标元数据，不读取宿主正文。
- **退格保留引号配对**：修正拼音时只清除字母／数字类别判断，保留已经输出的中文单、双引号开闭状态；真正的上下文边界仍重置配对。正常引擎与引擎不可用回退采用相同规则。
- **MSIX 内更新入口**：软件更新和每日检查统一经可信桌面 helper 的脱包 relay。更新偏好在确认无包身份后读取；每日检查仍须用户开启且距上次检查满一天，安装仍须另行确认。安装核心的包身份拒绝保留。
- **较大离线队列同步**：按 JSON 编码后的 UTF-8 字节数顺序分批，每批正文不超过 900,000 字节，避免触及后端的 1,000,000 字节上限。后续批次或词表快照失败时保留待同步事件，重试复用原 UUID；账号会话改变时停止后续批次。本地学习与账号同步的范围保持独立。

新增回归使用自有隔离 TSF 宿主、固定合成输入、模拟服务和临时存储；合成宿主不等于 Chrome／钉钉等实际应用，也不等于物理键盘验收。真实应用中连续输入与导航、退格后闭引号、MSIX 手动／每日更新以及较大真实账号队列同步仍待逐项验收。本机安装已按用户后续明确授权完成，未切换输入源、关闭宿主或发布更新。用户需保存工作后完全重开待测应用，再选择灵果测试。

### API 设置与整句翻译 · 0.1.17 开发源码

2026-10-13已按用户请求在安装目录的0.1.17设置页完成真实保存与启用，MiniMax国内接口及 `MiniMax-M2.7-highspeed` 的生产helper单次请求成功。该结果验证设置／凭据／授权／响应；候选触发、取消与英文上屏仍需实际宿主键盘验收，其他服务验收边界见[QA](QA.md)。

在设置“翻译”页填写完整 HTTPS Chat Completions 接口地址、模型名和 API 密钥，可选 MiniMax 国内／国际预设；参考模型为 `MiniMax-M2.7-highspeed`，能否使用需以服务账号权限为准。在线翻译首次默认关闭。预设只填字段；“保存并启用 AI”保存并开启，但该动作不发送测试或翻译请求。首次保存必须有密钥，同一完整地址后续留空才可保留原密钥；密钥由无包身份辅助进程保存在 Windows 凭据管理器，不写 JSON、日志或命令行。“使用本机翻译”关闭在线请求并保留密钥。

“准备本地整句翻译…”采用 Windows 本机方案，不能运行 Mac 的 Apple Translation。当前只接受 `127.0.0.1`／`::1` 回环上的 Ollama，以及用户已下载的本地中英文模型。准备操作先核对 `/api/status` 的 `cloud.disabled=true`、已安装模型的摘要与大小，再用固定测试句验证本机调用；模型不满足条件时拒绝请求。该操作会访问本机服务，与不联网的 API 设置保存是两条路径。本项目不下载模型，也不替用户启用服务；当前未完成真实本机模型验收。

Mac 从输入源菜单“本地学习记录…”或“设置 → 学习”进入；Windows 从候选窗设置（或 Ctrl＋Shift＋P）选择“本地学习记录…”。窗口可单独关闭，正常候选仍不抢宿主键盘焦点。文件位置为 Mac 的 `~/Library/Application Support/BilingualCompanion/LocalWords/words.json` 和 Windows 的 `%LOCALAPPDATA%\LingoMate\LocalWords\words.json`；每份文件最多 5,000 个词条，只保存聚合元数据，不保存正文、剪贴板、原始拼音或时间顺序输入历史。

两端采用跨进程文件锁及原子替换；损坏或超限文件保留并报告错误，不自动清空。Windows 在异步宿主编辑成功后记录，存储工作在后台执行，并将已加载模块保留至宿主退出，避免后台线程退出时的卸载竞争；升级后需重新打开宿主应用；保存失败不会撤销已输入文本。导出包含全部本地词条，使用 UTF-8 CSV 并防止电子表格公式注入。删除后，再次确认输出该词会重新建档。

## 构建与检查

Windows 日常开发使用 `codex/windows-dev` 分支，相关修改通过 Pull Request 请求合并到 `main`。每次提交只包含当前任务的改动，并记录自动检查与 Windows 实机验证范围；PR 合并后同步最新 `origin/main`。完整流程见 [协作维护说明](../CONTRIBUTING.md#开发与合并)。

面向同事的安装形式为安装 EXE，使用 Inno Setup 6 构建，详见 [安装包与同事试用](../docs/PACKAGING.md#windows-构建与安装)。安装器沿用当前用户目录与文件校验流程，保留历史版本；已上传维护者 Release 草稿，尚未提供公开下载。引擎 EXE 与安装 EXE 是不同文件。

准备 Windows 64 位 PowerShell、Git、Rustup、Python 3.10+，以及带 MSVC 与 Windows SDK 的 Visual Studio C++ 构建工具。执行：

```powershell
git clone https://github.com/jizw0704-source/lingomate.git
cd lingomate
git switch codex/windows-dev
./native-windows/tools/setup.ps1
./native-windows/tools/build.ps1
./native-windows/tools/check.ps1
```

准备脚本使用 Rust 1.96.0 与固定上游快照，发现已有源码改动时停止并保留文件。构建产物位于 `native-windows/package/windows-x64/`，包括 TSF DLL、本地核心 `lingomate_engine.dll`、独立 `lingomate-desktop.exe`、共享命令行引擎、数据与来源说明。构建和检查不会安装或选择输入法；不另建 Windows 功能分支。

构建／检查默认以 `--wordnet-in-memory` 下载官方固定 WordNet 并核验大小、SHA-256及完整许可，不写回被本机安全软件改写的旧缓存。若固定源下载超时，可显式提供已经下载的原始官方归档；依然执行同一固定摘要、大小和许可检查，不能使用解压目录或异常缓存代替：

```powershell
./native-windows/tools/build.ps1 -WordNetSource 'C:\path\WordNet-3.0.tar.gz'
./native-windows/tools/check.ps1 -WordNetSource 'C:\path\WordNet-3.0.tar.gz'
```

对应 Python 参数为 `--wordnet-source <归档路径>`，与 `--wordnet-in-memory` 互斥；Windows 脚本按是否提供 `-WordNetSource` 选择其中一种。本轮最终检查用已有、重新核验过的官方固定归档完成，旧异常 GZip 保留。词性来源、生成表和打包许可没有变化。

仓库的 Windows 检查流程执行 MSVC 构建、PowerShell 语法检查、Rust 格式与 Clippy、真实引擎回归及 DLL 类厂生命周期检查。流程不登记系统输入源，也不发布完整数据或安装包。检查结果见 [验证记录](QA.md)。

已在授权的本机试用范围安装完整可信包后，可单独检查 Windows 的真实加载路径：

```powershell
./native-windows/tools/test_system_profile.ps1 -Package ./native-windows/package/windows-x64 -OwnFocus
```

这项显式检查不属于默认检查或 CI。它只聚焦自己的空测试窗口，在自身线程切换并恢复 profile；不输入按键、不改变全局默认源。系统拒绝前台焦点时明确报告未验证，不绕过焦点限制。真实应用输入仍须人工验收。

`tools/test_helper_identity.ps1` 是另一个手动 opt-in 调试器身份探针，默认不执行动作，也不加入默认检查或 CI。明确指定已有应用包的名称、发布者、版本和 AppId 后，它只启动自有测试进程，核对真实包内父进程到生产 relay／最终无包身份 helper 的身份链；本轮两种子进程策略通过。它不修改包元数据、不登记输入法、不激活真实应用UI、不读配置／凭据／输入，也不能代替该应用的键盘、VFS或真实翻译验收。完整步骤和边界见[QA](QA.md)。

## 安装与使用

在 Windows 机器完成检查后运行：

```powershell
./native-windows/tools/install.ps1
```

安装脚本校验完整包，将新版本放入 `%LOCALAPPDATA%\LingoMate\Windows\` 的独立目录，并登记本项目的 COM 类与中文输入配置。COMLESS 加载需要自有 CLSID 的 HKLM 映射，普通权限安装会弹出同一账号的 UAC 请求；不接受改用另一个管理员账号。脚本保持 HKCU／HKLM 映射一致，旧版本文件保留，失败尝试恢复原登记并报告恢复结果。0.1.16 已验证普通权限脚本的实际 UAC 往返；安装 EXE 的完整安装／卸载界面流程仍待验证。

完成后通过 Windows 输入切换器手动选择“灵果 · LingoMate”。如系统要求添加中文语言或重新登录，按系统提示处理；脚本不自动重启、注销、切换输入法或关闭其他应用。

| 操作 | 功能 |
| --- | --- |
| 空格 / 数字 1–5 | 确认当前页中文 |
| Shift＋空格 | 确认当前选中的英文译法 |
| Enter | 有组合输入时提交原样字母；空回车由当前应用处理 |
| Tab / Shift＋Tab | 展开及切换译法 |
| ↑ / ↓ | 切换当前页候选 |
| PageUp / PageDown，`-` / `=` | 翻页 |
| Esc | 收起译法，再取消输入 |
| 单按并松开 Shift | 切换中文 / 英文直输 |
| F6（0.1.17） | 切换普通中文 / 中英候选，保留拼音 |
| Ctrl＋Shift＋P（0.1.17） | 循环自动 / 固定中文 / 固定英文标点 |
| 候选齿轮 / 语言栏设置 / Ctrl＋逗号（0.1.17） | 打开独立五页设置 |
| ⚙ 设置中的“检查版本更新…” / Ctrl＋Shift＋U | 打开独立软件更新窗口 |

可使用 `wo`＋空格、`AI`＋回车、`xuexi`＋空格检查“我AI学习”；输入 `shi` 检查分页，输入 `xuexi` 检查第三种译法。实际键盘验收应包括记事本、浏览器、聊天应用及反复焦点切换。

卸载前先选择其他输入法，再运行：

```powershell
./native-windows/tools/uninstall.ps1
```

卸载只撤销本项目登记，保留版本文件用于回退，不清理其他输入法或个人数据。

## 远程版本更新

完成 0.1.1 或后续版本的首次安装后，可点击候选窗口“⚙ 设置 → 检查版本更新…”，或在灵果处于活动状态时按 Ctrl＋Shift＋U，打开“软件更新”。首次安装可使用维护者提供的安装 EXE，也可自行构建；0.1.0 不含更新程序，需要先手动升级一次。

窗口依次提供检查、更新说明、下载校验和确认安装。每日自动检查默认关闭，可在窗口中开启；启用后，在灵果激活且距上次检查超过 24 小时时检查，仅发现新版本时显示窗口，不自动下载或安装。网络失败不影响输入，可手动重试。

新版本安装至独立目录。校验失败不会登记新版本，登记失败会尝试恢复原登记；若恢复也失败，界面明确报告。更新完成后，请切换到其他输入法，保存工作并重新打开使用灵果的应用，再选择灵果。窗口可“恢复上一版本”，回退后同样需要重新打开应用。程序不强制关闭应用、重启输入服务或重新登录。

更新来源固定为本项目 GitHub Releases，不需要账号或 API 密钥。检查和下载由独立桌面进程执行，不在 TSF 按键回调中进行网络请求，也不发送输入内容、学习记录或账号信息。公司网络连通性及 PowerShell 运行策略需实机验证。

当前尚未公开发布 Windows 更新包；新词库已改用许可明确来源，开放下载仍需完成实机验收、发行签名及对应源码交付。更新使用 HTTPS 发布源及 SHA-256 校验，不代表已完成 Windows 发行签名。详见 [Windows 更新与发布](UPDATES.md)。

## 数据、依赖与验证边界

Windows 客户端不读取宿主正文、选区内容或剪贴板，不保存输入日志；只核对自有组合范围和光标位置元数据，以防旧回复覆盖宿主编辑。拼音与候选在本进程后台线程调用同目录核心；共享命令行桥接保留。0.1.17 的可选在线翻译、账号和凭据仅由独立无包身份 helper 处理，键盘回调不等待网络。中文记忆不上传；英文学习本地保存，账号仅同步已授权的所选词条，整句不进入同步。默认关闭的诊断仅记录固定激活／模式／焦点元数据，不记录输入内容。

Windows 平台接口使用 Microsoft `windows` / `windows-core` Rust 绑定；JSON 协议复用既有 serde 与 serde_json。平台绑定只在 Windows 编译，新增依赖用于系统接口接入。代码采用 GPL-3.0-or-later，当前词库与改编数据为 CC BY-SA 4.0，来源及旧版审计见 [第三方来源](../docs/THIRD_PARTY.md)。

macOS 上的 Windows 目标类型检查与引擎回归不等同于 Windows 实机输入验收。当前尚未发布正式 Windows 安装包，系统登记、应用兼容性、候选焦点、Shift 实际事件、缩放及长期稳定性仍待验证。
