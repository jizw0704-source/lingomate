## 重启后的真实应用反馈 · 2026-10-13

0.1.16 在正常重启后仍未通过跨应用验收：ChatGPT 显示拼音／候选，Chrome、钉钉、grokbot 只输出字母且无候选窗；Windows 搜索栏能切到灵果，实际仍使用微软输入法。已核对 ChatGPT 加载新 DLL 并成功激活，而当前 Chrome、钉钉和 SearchHost 未加载灵果 DLL。继续调查系统选择到宿主加载的链路，不能由下列隔离或系统探针的通过推定真实应用已解决。详见[最新验证记录](QA.md)和[根因调查](../docs/WINDOWS-ROOT-CAUSE-AUDIT.md)。

根因已在包外终端确认：上述安装和系统探针都在 Codex 桌面应用（MSIX 包）的终端中执行，文件与 HKCU 登记被重定向到该包私有位置，只有该应用能载入灵果。下文“已安装”“系统加载通过”只在该包视图内成立。安装脚本现拒绝在有包身份的进程中运行；需在普通 PowerShell 重新安装后再验收。

## 外观、字号、标点与系统图标 · 0.1.9

候选窗点击“⚙ 设置”，或按 Ctrl＋Shift＋P，选择“外观”“候选字号”“标点规则（当前应用）”。默认白色、标准字号（中文 15／英文 13）、自动标点；外观和字号保存至 `HKCU\Software\LingoMate\Candidates`，在其他应用激活输入法时加载，标点规则仅作用于当前应用会话。更改外观或字号保留拼音、候选页及当前译法；学习记录和更新窗口也跟随外观，系统高对比度优先。

中文候选后使用中文标点，英文候选及回车确认字母后使用英文标点；可固定为中文或英文。支持配对引号 `“”`／`‘’`、括号 `（）`／`【】`、书名号 `《》` 及顿号 `、`。拼音中的单引号仍用于分隔音节。数字的小数点、时间冒号和日期斜杠默认保留半角；输入 `https:`、`www.` 或邮箱 `@` 后保留连续地址字符，空格结束地址输入。原样字母按回车后恢复拼音组合。数字保护在固定中文模式下按中文规则，网址／邮箱保护始终生效。此功能仅根据本输入法处理过的字符判断，不读取或推断粘贴文本、宿主正文或光标前的文本。

字号档位为小／标准／大／特大（兼容既有 16／18／20／22 偏好值），使用系统 Microsoft YaHei UI 及系统字形回退，不分发第三方字体。候选按显示器 DPI 缩放，窄幅布局可换行，点击区域与绘制使用同一套布局；仍保持每页五项和原有编号。输入源采用 DLL 内嵌“果”字图标，包含多种尺寸，无额外安装图标文件。以上是已实现的客户端功能，Windows 11 实体键盘、系统主题切换、多屏、高对比度及输入源图标展示须由 Wright 在实机核对。

## 候选空白与恢复 · 2026-10-12 本地修复

## 英文词性设置

在候选窗顶部点击 **设置**，勾选或取消“显示词性”；也可按 **Ctrl＋Shift＋P** 打开此菜单。开关同时控制主要英文候选与展开译法，并保存至当前用户的 `HKCU\Software\LingoMate\Candidates`，重启后保留；切回已有输入会话时重新读取。此快捷键不切换标点，与 Mac 的同名快捷键用途不同。

默认显示 `n.`、`v.`、`adj.`、`adv.` 等缩写，多词性可显示为 `n./v.`。词性来自既有人工用法和固定 WordNet 3.0 索引，完整词无法核对时不标注。它仅为学习提示，不判断整句语法，也不改变提交英文。见 [词性来源与许可](../docs/THIRD_PARTY.md#英文词性来源)。

Windows 日常开发使用 `codex/windows-dev` 分支，相关修改通过 Pull Request 请求合并到 `main`。每次提交只包含当前任务的改动，并记录自动检查与 Windows 实机验证范围；PR 合并后同步最新 `origin/main`。完整流程见 [协作维护说明](../CONTRIBUTING.md#开发与合并)。

## 安装与使用

在 Windows 机器完成检查后运行：

```powershell
./native-windows/tools/install.ps1
```

安装脚本校验完整包，将新版本放入 `%LOCALAPPDATA%\LingoMate\Windows\` 的独立目录，并登记本项目的 COM 类与中文输入配置。COMLESS 加载需要自有 CLSID 的 HKLM 映射，普通权限安装会弹出同一账号的 UAC 请求；不接受改用另一个管理员账号。脚本保持 HKCU／HKLM 映射一致，旧版本文件保留，失败尝试恢复原登记并报告恢复结果。0.1.16 已验证普通权限脚本的实际 UAC 往返；安装 EXE 的完整安装／卸载界面流程仍待验证。

完成后通过 Windows 输入切换器手动选择“灵果 · LingoMate”。如系统要求添加中文语言或重新登录，按系统提示处理；脚本不自动重启、注销、切换输入法或关闭其他应用。

| 操作 | 功能 |
| --- | --- |
| 空格 / 数字 1–5 | 确认当前页中文 |
| Shift＋空格 | 确认当前选中的英文译法 |
| Enter | 有组合输入时提交原样字母；空回车由当前应用处理 |
| Tab / Shift＋Tab | 展开及切换译法 |
| ↑ / ↓ | 切换当前页候选 |
| PageUp / PageDown，`-` / `=` | 翻页 |
| Esc | 收起译法，再取消输入 |
| 单按并松开 Shift | 切换中文 / 英文直输 |
| ⚙ 设置中的“检查版本更新…” / Ctrl＋Shift＋U | 打开独立软件更新窗口 |

可使用 `wo`＋空格、`AI`＋回车、`xuexi`＋空格检查“我AI学习”；输入 `shi` 检查分页，输入 `xuexi` 检查第三种译法。实际键盘验收应包括记事本、浏览器、聊天应用及反复焦点切换。

卸载前先选择其他输入法，再运行：

```powershell
./native-windows/tools/uninstall.ps1
```

卸载只撤销本项目登记，保留版本文件用于回退，不清理其他输入法或个人数据。

## 远程版本更新

完成 0.1.1 或后续版本的首次安装后，可点击候选窗口“⚙ 设置 → 检查版本更新…”，或在灵果处于活动状态时按 Ctrl＋Shift＋U，打开“软件更新”。首次安装可使用维护者提供的安装 EXE，也可自行构建；0.1.0 不含更新程序，需要先手动升级一次。

窗口依次提供检查、更新说明、下载校验和确认安装。每日自动检查默认关闭，可在窗口中开启；启用后，在灵果激活且距上次检查超过 24 小时时检查，仅发现新版本时显示窗口，不自动下载或安装。网络失败不影响输入，可手动重试。

新版本安装至独立目录。校验失败不会登记新版本，登记失败会尝试恢复原登记；若恢复也失败，界面明确报告。更新完成后，请切换到其他输入法，保存工作并重新打开使用灵果的应用，再选择灵果。窗口可“恢复上一版本”，回退后同样需要重新打开应用。程序不强制关闭应用、重启输入服务或重新登录。

更新来源固定为本项目 GitHub Releases，不需要账号或 API 密钥。检查和下载由独立桌面进程执行，不在 TSF 按键回调中进行网络请求，也不发送输入内容、学习记录或账号信息。公司网络连通性及 PowerShell 运行策略需实机验证。

当前尚未公开发布 Windows 更新包；新词库已改用许可明确来源，开放下载仍需完成实机验收、发行签名及对应源码交付。更新使用 HTTPS 发布源及 SHA-256 校验，不代表已完成 Windows 发行签名。详见 [Windows 更新与发布](UPDATES.md)。

## 数据、依赖与验证边界

Windows 客户端不读取宿主正文、选区或剪贴板，不保存输入日志，也不调用在线翻译或账号服务。当前拼音和候选请求在本进程后台线程调用同目录核心；共享命令行桥接保留供其他客户端与回归检查。确认后的中文选词记忆和英文学习记录仅存本机，使用独立文件与有界并发保护。默认关闭的诊断仅记录固定激活／模式／焦点元数据，不记录输入内容。

Windows 平台接口使用 Microsoft `windows` / `windows-core` Rust 绑定；JSON 协议复用既有 serde 与 serde_json。平台绑定只在 Windows 编译，新增依赖用于系统接口接入。代码采用 GPL-3.0-or-later，当前词库与改编数据为 CC BY-SA 4.0，来源及旧版审计见 [第三方来源](../docs/THIRD_PARTY.md)。

macOS 上的 Windows 目标类型检查与引擎回归不等同于 Windows 实机输入验收。当前尚未发布正式 Windows 安装包，系统登记、应用兼容性、候选焦点、Shift 实际事件、缩放及长期稳定性仍待验证。
